ANÁLISIS PROFUNDO DEL SISTEMA: MANHWA SITES RANKING API

1. VISIÓN GENERAL
La aplicación es un ecosistema automatizado de descubrimiento y auditoría de sitios web de Manhwa. A diferencia de un directorio estático, esta app se comporta como un "organismo vivo" que busca, mide y clasifica sitios de forma autónoma.

2. ARQUITECTURA DE TRES CAPAS (EL "MOTOR")

A. Capa de Descubrimiento (Discovery Phase)
- Implementada en: DiscoverSitesJob -> CrawlerService.
- Lógica: Realiza búsquedas proactivas en Google con queries estratégicas como "read manhwa online".
- Resiliencia: Si la API de Google falla (por límites de cuota), el sistema tiene un mecanismo de "Autocuración" que cambia automáticamente a scraping de DuckDuckGo y Bing.
- Inteligencia: Limpia y normaliza URLs, descartando dominios irrelevantes (redes sociales, Wikipedia, etc.) mediante una lista negra (blockedDomains).

B. Capa de Extracción de Métricas (Scraping Phase)
- Implementada en: ScrapeSitesJob -> ScraperManager -> TrafficService.
- Obtención de Datos: 
    * Tráfico Real: Intenta obtener el "Global Rank" real de los sitios mediante scraping de proveedores de datos de popularidad (siterankdata.com).
    * Algoritmo de Estimación: Si no hay datos reales, utiliza una fórmula de distribución logarítmica (rankToVisits) para convertir el ranking mundial en visitas diarias estimadas.
    * Mocking de Rendimiento: Actualmente usa placeholders para SEO y Speed, diseñados para ser reemplazados por APIs como Google PageSpeed.

C. Capa de Inteligencia de Ranking (Scoring Phase)
- Implementada en: RankingJob -> RankingService.
- Algoritmo de Decisión: Aplica una fórmula ponderada (Weighted Average):
    * 50% - Tráfico (Volumen de usuarios).
    * 20% - SEO (Visibilidad en buscadores).
    * 20% - Speed (Experiencia de usuario).
    * 10% - Uptime (Fiabilidad).
- Dinamismo: En cada ejecución, el sistema actualiza no solo el puntaje, sino que reasigna las posiciones (1 al N) basándose en la competencia actual.

3. COMPONENTES TÉCNICOS CLAVE
- Framework: AdonisJS 6 (TypeScript).
- Base de Datos: SQLite (Ubicada en /tmp para facilitar despliegues rápidos y snapshots de datos).
- Automatización: Scheduler integrado que corre ciclos de descubrimiento diarios y ciclos de auditoría/ranking cada 6 horas.
- Seguridad: Sistema de autenticación JWT para proteger el perfil del usuario, aunque el ranking es público.

4. FORTALEZAS DEL DISEÑO
- Desacoplamiento: El uso de "Managers" (como ScraperManager) permite añadir scrapers específicos para sitios que requieran lógica especial (bypass de Cloudflare, etc.) sin afectar al resto del sistema.
- Escalabilidad: Los Jobs están diseñados para procesar sitios de forma iterativa, permitiendo que la base de datos crezca de 10 a 1000 sitios sin cambios estructurales.

5. ÁREAS DE EVOLUCIÓN DETECTADAS
- Integración de PageSpeed API: Para sustituir los valores aleatorios de SEO/Speed por datos técnicos reales.
- Histórico de Ranking: El sistema actual sobreescribe el ranking; se podría implementar una tabla de histórico para generar gráficas de "Tendencia" (subidas/bajadas).
- Robustez en Crawling: El fallback de DuckDuckGo detecta bots; se requeriría una rotación de Proxies o User-Agents más agresiva.

CONCLUSIÓN:
Es una herramienta de monitoreo competitiva altamente modular. Su mayor valor reside en la automatización del descubrimiento de sitios, lo que le permite detectar nuevos competidores en el mercado de manhwas antes que un humano lo haría manualmente.
